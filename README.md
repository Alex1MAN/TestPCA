# ConsolePCA

Консольное приложение на C# для анализа главных компонент (PCA) по данным из Excel. Приложение читает числовую таблицу, стандартизирует переменные, строит PCA-модель, выводит объяснённую дисперсию и сохраняет графики в PNG.

## 1. Что понадобится

- Windows и установленный .NET 8 SDK — именно SDK, а не только Runtime.
- Интернет для первоначальной загрузки пакетов NuGet.
- Исходники проекта.
- Excel-файл с данными: `NiCu100.xlsx`, `NiCu1000.xlsx` или собственная таблица.
- Visual Studio необязательна: приложение можно собрать и запустить из PowerShell.

Официальная страница загрузки .NET 8: https://dotnet.microsoft.com/download/dotnet/8.0

После установки SDK откройте новое окно PowerShell и выполните:

```powershell
dotnet --list-sdks
```

В списке должна присутствовать версия `8.0.xxx`. Если команда не найдена, проверьте установку SDK и перезапустите терминал.

## 2. Скачайте исходники

Самый простой способ без установки Git:

1. Откройте страницу этого репозитория на GitHub.
2. Нажмите `Code` → `Download ZIP`.
3. Распакуйте архив, например в `C:\Projects\ConsolePCA`.
4. Найдите каталог, в котором лежит `TestPCA.csproj`.

Дальнейшие команды выполняйте именно в каталоге с `TestPCA.csproj`. Если после распаковки появился дополнительный вложенный каталог, перейдите в него.

Основные файлы проекта:

```text
TestPCA.sln
TestPCA.csproj
Program.cs
DataProcessor.cs
PcaModel.cs
Visualization.cs
```

Файлы `NiCu100.xlsx` и `NiCu1000.xlsx` могут не входить в репозиторий. В этом случае получите их у автора или создайте собственный файл по инструкции ниже.

## 3. Подготовьте Excel-файл

Приложение читает первый лист книги `.xlsx`.

Требования:

- Первая используемая строка — заголовки переменных.
- Каждая следующая строка — отдельное наблюдение.
- Каждый столбец — числовая переменная.
- Для полного запуска с графиками PC1/PC2 нужно минимум два числовых столбца и две подходящие строки данных.
- Для осмысленной проверки используйте больше наблюдений, чем в минимальном примере.
- Хотя бы один столбец должен иметь ненулевую дисперсию.
- Не добавляйте текстовые идентификаторы, комментарии, даты и итоговые строки в область числовых данных.
- Для простого запуска начинайте таблицу с ячейки A1.

Строки с пустыми или нечисловыми ячейками пропускаются целиком. Формат файла `.csv` напрямую не поддерживается: сохраните таблицу как `.xlsx`.

### Небольшая таблица для проверки

Создайте книгу с такой таблицей на первом листе:

| X1 | X2 | X3 |
|---:|---:|---:|
| 1 | 2 | 5 |
| 2 | 1 | 4 |
| 3 | 4 | 3 |
| 4 | 3 | 2 |
| 5 | 6 | 1 |

Сохраните её как `demo.xlsx` рядом с `TestPCA.csproj`. Эта таблица предназначена для проверки загрузки, расчёта и сохранения графиков, а не для содержательной интерпретации PCA.

## 4. Восстановите зависимости и соберите проект

Откройте PowerShell и перейдите в каталог проекта. Замените пример пути своим:

```powershell
cd "C:\Projects\ConsolePCA"
dotnet restore .\TestPCA.csproj
dotnet build .\TestPCA.csproj
```

`dotnet restore` скачивает зависимости, а `dotnet build` собирает приложение. Продолжайте после завершения сборки без ошибок.

Версии пакетов уже заданы в проекте:

| Пакет | Версия | Назначение |
|---|---|---|
| ClosedXML | 0.104.1 | Чтение Excel |
| MathNet.Numerics | 5.0.0 | Матричные вычисления |
| ScottPlot | 5.0.35 | Построение графиков |

Не обновляйте пакеты вручную перед первым запуском: код рассчитан на эти версии API.

## 5. Запустите приложение

Для созданного тестового файла:

```powershell
dotnet run --project .\TestPCA.csproj -- "demo.xlsx"
```

Для файла из набора данных:

```powershell
dotnet run --project .\TestPCA.csproj -- "NiCu100.xlsx"
```

Для файла в другом каталоге передайте полный путь:

```powershell
dotnet run --project .\TestPCA.csproj -- "C:\Data\NiCu100.xlsx"
```

Разделитель `--` отделяет параметры команды .NET от аргументов приложения. Путь к Excel передаётся первым аргументом. Если он содержит пробелы, заключите его в кавычки.

Без аргумента приложение ищет `NiCu100.xlsx` в текущем рабочем каталоге:

```powershell
dotnet run --project .\TestPCA.csproj
```

## 6. Проверьте результат

В консоли должны появиться:

1. Количество загруженных строк и столбцов.
2. Названия переменных.
3. Количество главных компонент.
4. Доля объяснённой дисперсии первых компонент.
5. Сообщения о сохранении графиков.
6. Сводка накопленной объяснённой дисперсии и сообщение о завершении.

Для таблицы `demo.xlsx` ожидается загрузка 5 строк данных и 3 столбцов с именами `X1`, `X2`, `X3`.

В каталоге `output` должны появиться:

| Файл | Что показывает |
|---|---|
| `scree_plot.png` | Объяснённую дисперсию каждой компоненты |
| `scores_plot.png` | Наблюдения в координатах PC1 и PC2 |
| `loadings_plot.png` | Коэффициенты исходных переменных в PC1 и PC2 |

Откройте все три PNG и убедитесь, что они читаются и содержат графики.

Каталог `output` создаётся относительно текущего рабочего каталога процесса. При запуске командами выше это каталог, из которого вы выполняете команды. При повторном запуске одноимённые изображения перезаписываются: скопируйте их заранее, если хотите сравнить два набора данных.

Метод построения кумулятивной дисперсии есть в `Visualization.cs`, но текущий `Program.cs` его не вызывает. Поэтому четвёртый график автоматически не создаётся.

Наличие сообщения об ошибке означает, что запуск не прошёл полностью, даже если остались PNG от предыдущего запуска. Перед контрольным запуском можно удалить старую папку `output`, если в ней нет нужных результатов.

## 7. Запуск из Visual Studio

1. Откройте `TestPCA.sln` в Visual Studio с поддержкой .NET 8.
2. Дождитесь восстановления пакетов NuGet.
3. Выполните `Build` → `Build Solution`.
4. Для первого контрольного запуска откройте `View` → `Terminal`.
5. Перейдите в каталог с `TestPCA.csproj`, если терминал открыт в другом месте.
6. Выполните:

```powershell
dotnet run --project .\TestPCA.csproj -- "C:\Data\NiCu100.xlsx"
```

Полный путь к данным помогает избежать путаницы с рабочим каталогом.

## 8. Частые проблемы

### Команда dotnet не найдена

Установите .NET 8 SDK, затем закройте и заново откройте PowerShell или Visual Studio. Повторите `dotnet --list-sdks`.

### Файл не найден

Проверьте имя, расширение и путь. Попробуйте передать полный путь в кавычках. Без аргументов программа ищет именно `NiCu100.xlsx`, а не `demo.xlsx`.

### Нет подходящих данных или загружено меньше строк, чем ожидалось

Проверьте первый лист. Строки с пропусками или нечисловыми значениями исключаются целиком. Проверьте, что в таблице нет текстового столбца с названиями образцов.

### Недостаточно компонент для графика

Полный сценарий в `Program.cs` рассчитан минимум на два столбца. Используйте таблицу с двумя или более числовыми переменными. PCA одной переменной требует отдельной обработки в программе.

### Суммарная дисперсия равна нулю

Проверьте, что данные не состоят только из постоянных значений. Для анализа необходимы изменяющиеся переменные.

### Не удалось восстановить NuGet-пакеты

Проверьте подключение к интернету и доступ к источнику NuGet, затем повторите:

```powershell
dotnet restore .\TestPCA.csproj
```

### PNG не найдены

Проверьте рабочий каталог терминала и сообщения приложения. Если расчёт завершился ошибкой до сохранения изображений, графики не будут созданы.

## 9. Ограничения и особенности

- Анализ выполняется по первому листу Excel.
- Стандартизация включена всегда: из каждого столбца вычитается среднее и выполняется деление на стандартное отклонение.
- Пропуски не заполняются: строки с неподходящими значениями исключаются.
- `Loadings` в этом проекте — собственные векторы ковариационной матрицы, а не отдельно вычисленные корреляции переменных с компонентами.
- Имена столбцов не являются подписями отдельных наблюдений на scores plot.
- Проверка по этой инструкции — ручной функциональный тест. Отдельный проект автоматических тестов в составе решения не предусмотрен.
- Успешное сохранение графиков проверяет работоспособность приложения, но само по себе не подтверждает корректность исходных данных или научной интерпретации результатов.
